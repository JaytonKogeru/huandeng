## 这次解决了什么

### 更清楚的工作台

顶栏收成一条横向信息带：项目名、当前 Main/Presentation、保存状态和文件动作。长名称有序截断，正常连接不再占一整行。静态格式与 MP4 共用一个导出窗口，范围、设置、进度和结果集中处理，演示仍能直接进入。

工具栏“素材”进入同一个素材库；设备导入和库内“导入并放置”说明目标当前页。原来的图片路径输入弹窗被移除，拖放、粘贴、比例和 Undo 保留。保存动作明确为“保存页面”，项目、Story、图表和时间线的独立草稿仍有自己的确认与失败恢复。

动画预览让出基础属性栏，结束后恢复选择和手动面板偏好。1040×680 小窗口在“适合窗口”模式下打开时间轴时整页可见；真实测试发现并修复了底部裁切。按压、焦点和弹层反馈沿用现有设计系统，减少动态效果也覆盖 Portal。窗口缩小时仍有进一步改善空间，尤其是时间轴可调高度和常驻说明的收拢。

### 第一条动画更容易做出来

新轨道建立后选中终点，并提示修改终点数值后预览；起点与终点最初同值，避免擅自猜测作者的动作。可见时间统一使用秒，精度到 0.001 秒，磁盘继续保存整数毫秒。快捷键帮助补齐时间轴实际行为，快速缩略图切页的焦点竞争也已修复。

### 能交付真正的动画视频

在顶部 **导出 → 动画视频 · MP4** 中选择当前页或当前集合。重复页面按每次出现输出，固定版本继续使用归档画面。视频按确定时刻逐帧采样，字体、图片、公式等就绪后再编码；编码速度不改变成片的时间与动作。

当前支持 **720p/1080p、24/30fps、H.264 MP4，无音轨**。静页默认 3 秒，动画末态默认 1 秒；cue 的额外停留由用户设置，开始前显示总时长。可以关闭弹层继续编辑，再回来查看进度、取消或下载；导出使用开始时冻结的文稿与素材。

视频需要带 libx264 的 FFmpeg。本机现有 PATH 编码器已在正式安装及普通项目窗口中验证；安装包不自动捆绑或下载 FFmpeg。其他机器未配置时会说明原因。自主播放 GIF/APNG/动态 WebP/动画 SVG 目前明确拒绝，先换为静态素材即可导出 PPTD 关键帧动画。

**PNG/PDF/PPTX 继续交付基础版式。** 报告明确标出动画没有进入这些静态文件；MP4 支持不等于原生 PowerPoint 动画已完成。详细操作见 [动画指南](ANIMATION.md)。

### 资源有明确生命周期

外部页面历史改为摘要索引与 8 条/约 4 MiB 热全文，旧磁盘历史仍可随时读取和恢复。普通保存减少重复全项目读取。导出完成后释放冻结状态和素材内存，下载改为独立文件流；旧任务下载不会被之后同名导出覆盖。任务有数量、时效、取消及关闭清理边界，外部文件占用产生明确警告和有限重试。

缩略图和素材网格可使用 320/640px 派生图，画布、详情和成品保留原尺寸。派生缓存、排队、像素和读取字节都有上限；工具缺失时回退经过版本核对的原图。旧 revision 不会偷偷返回新图，普通文字编辑也不会让所有图片地址变动。

## 性能判断与保留问题

本轮的确定收益是减少保存链路重复工作、给历史和导出资源设定边界，以及让高清缩略图真正降采样。Windows 隔离服务流程中，40 轮页面读取从 6600 次降为 3400 次，周期中位从 299.00 降为 207.97 ms；它不是 GUI 全流程保存延迟。

实际 80 页 50 轮中，文档服务工作集约 212–223 MiB 波动；renderer 仍从约 159 增至 497 MiB，显式 GC 后仍约 398 MiB。**长会话 renderer 内存增长尚未解决。** 高清场景最后一个循环出现短期平台，不能替代数小时编辑证据。

文件持久化观测与操作确认必须分开：本次 50 轮分别为 245.75 与 403.80 ms 中位。为核查与 v0.6 历史数据的差异，又使用同一脚本做相邻各 20 轮对照；结果与解释记录在 Validation。不能把内部工作量减少写成所有交互全面加速。

本地 MCP 现在有 **17 个工具**；包内 CLI 的真实 stdio 和真实导出任务状态已验收。实际 Codex/Claude 客户端安装、ChatGPT 私有连接、音轨/媒体时钟、运动路径、独立 occurrence 视觉变体、双屏彩排及 PPTX 往返均未在此版宣称完成。
