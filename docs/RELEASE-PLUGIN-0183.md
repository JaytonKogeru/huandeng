# HUANDENG plugin 0.18.3 · Story-led introductions

The previous artwork improved, but the introduction still did not explain why the founder built HUANDENG. This milestone rebuilds the narrative around the founder's spoken account and delivers six current editions inside the canonical repository.

Editor remains **0.18.0**; core npm remains **2.3.1**. This is an authoring-plugin, example and workspace milestone. Repository visibility remains private.

## The story behind the workflow

The introduction now starts with a lab meeting and the recognizable lack of a point in many polished AI slides. A small edit creating another whole-deck copy motivates stable page identity and page-level history. The limits of inspecting only screenshots motivate structured targeting alongside visual review. The human account comes first; page Story and speaking Notes carry that intent into the work.

Features then answer those motivations: PPTD and the project directory, Slide ID versus Position, page history, the asset library, the Editor views, and one Main collection reused in different talks. Real scientific figures, tables, an equation, product marks, localized UI evidence and purposeful backgrounds remain part of the introductions.

The founder's original story and checked technical facts are included with each portable project. The technical fact brief and root editions distinguish PPTD from an unpacked PPTX, avoid a first-inventor claim, and explain that recording Story does not guarantee model obedience. Native departures from those distinctions remain recorded below.

## Plugin guidance

Plugin 0.18.3 makes the human experience, decision and consequence the organizing thread. It requires page purposes and speaking Notes to be reviewed together, technical claims to stay within the sources, and interface screenshots to demonstrate a task.

Ordinary lists and paragraphs use coherent text objects. Genuine row/column comparisons use native tables. The guidance prohibits fake tables assembled from text boxes without imposing an arbitrary object limit on real diagrams, image annotations or scientific panels.

Native Codex and Claude installations use their supported commands. The dedicated DeepSeek configuration selects the same frozen guide without changing ordinary DeepSeek settings. Installation/cache inventories match all 24 package files, and the selected writer passes the runtime doctor.

The existing private account plugin was updated in place and read back. Its app binding, identity and audience were retained. Updating the owned record did not reinstall the previously removed duplicate account-backed installation.

## Validation and limits

Actual PowerPoint 16.0 inspection rendered all 135 Main pages read-only. The final Chinese punctuation and reference-thumbnail corrections were rechecked independently. Root brief historical pins were inspected separately. Both root Main files retain three native tables, one native chart and one Office equation; the brief's pinned historical chart uses an explicitly recorded image fallback.

Main export reports match current source revisions. Portable packaging checks source/reference closure, ZIP integrity and per-entry SHA-256. Release assets are checked against the frozen packaging manifest. Plugin tests and the repository formatting gate are recorded in the release evidence.

Technical completion, independent review and author acceptance are separate. This release provides review candidates; it does not record the author's acceptance of the new story.

## Workspace and startup

The cleanup covers the generic v013 files missed by the earlier prefix-only pass, obsolete installer payloads and retired worktrees. Unique private originals and source differences were preserved and verified in the existing ignored handoff area. Unrelated projects and possible concurrent user work remain intact.

Startup was measured with the installed 0.18.0 executable and an isolated profile. Empty Home became interactive in 1.854 seconds; opening the public sample in an existing window took 5.117 seconds; restoring it in a new process reached project readiness in 6.086 seconds. These are warm-cache observations during native trials. They identify serial project restoration as a concrete investigation path; no startup fix is claimed.
