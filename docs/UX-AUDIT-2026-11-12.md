# HUANDENG Editor — Workspace UX Audit (2026-11-12)

Scope: 0.22.1 desktop shell + React Editor with multiple open PPTD projects. Reviewed the two user-supplied real screenshots (DNA TT dark, Tag Binder light) and current project tabs, preferences, settings, shell, Home and export implementations.

## Fixed in the development tree (not yet published)

| Priority | Problem | Resolution |
| --- | --- | --- |
| P0 | Theme follows the project's localhost origin | Desktop `uiTheme` is the single source of truth, broadcast to every Project |
| P0 | Native titlebar uses OS theme even when Editor differs | Use Electron `nativeTheme.themeSource` based on desktop preference |
| P0 | Home stays light and was affected by an OS-dark media override | Home and tab shell now read the desktop theme, including forced light on dark OS |
| P1 | Settings do not explain global versus project-local effects | Explicit global theme/language, project-local panels, and global snapping descriptions |
| P1 | Theme save failures silently fail in secondary entry points | Settings errors shown; theme shortcut and command menu failures reported |

## Follow-up UX decisions

| Priority | Observed issue | Recommended change |
| --- | --- | --- |
| P1 | Panel widths, visibility and Notes dock persist separately per Project | Prefer one window-global layout across project tabs; migrate existing projectLayouts and synchronize rather than merely relabeling |
| P1 | Collapsed vertical rail displays two-letter codes without enough context | Show recognizable project names or context on keyboard focus; keep compact mode optional |
| P2 | Native tab chrome and the inner editor toolbar both show Project identity | Consolidate repeated title/status to reduce vertical space |
| P2 | Large number of editor toolbars and controls | Run an ordered first-run path and group actions by task rather than removing functionality blindly |
| P2 | Settings checkboxes and explanatory text are weakly grouped | Use clearer rows and control proximity; keep the settings dialog small-window accessible |
| P2 | The Fonts settings tab only previews and checks availability; it does not set a default font | Rename to Font check / 字体检查, or implement a real default-font preference |
| P2 | New Project uses a Windows save-file picker but creates a separate directory with `deck.pptd` | Replace with an explicit folder/name creation flow when revisiting onboarding |
| P2 | Home offers an interface language control but no theme control | Put application-global appearance controls in one discoverable menu accessible without opening a Project |
## Preference ownership contract

- Application-global: UI theme, UI language, tab orientation and collapse, snapping.
- Current behavior (remaining UX debt): panel visibility, dimensions and Notes dock are Project-local. Intended improvement: window-global panels in the same Editor window; keep slide zoom and selection independent.
- Project content: slides, Stories, Notes, assets, Sections, Presentations, named versions.
- Local viewport/session: current selection and active view; these must not become editable project content.
- Never infer global theme from a hidden Project's `localStorage`.

- Existing Workspace settings browser tests: 4 passed.
- Entire unit suite: 140 test files, 1,488 passed, 1 skipped (pre-existing skip).
- TypeScript typecheck and core build passed.
- UI screenshots were user-provided. E2E used separately initialized temporary PPTD projects in an ignored `.verification/` folder.
- Production 0.22.1 installation and user-authored slides were not modified by this source audit.

## Known scope

The theme patch intentionally does not migrate separate panel layouts or erase existing `projectLayouts`. Releasing and switching the real user's running Editor should be a separate controlled operation that saves unsaved work first. No public GitHub push is part of this audit.
