# HUANDENG v0.6 — 编辑工作台与时间线审计

日期：2026-11-08（Australia/Sydney）。基线：已安装 v0.5.0，运行时 `03a96957`，源码里程碑 `ef80f5b`。这轮将历次规格、v0.5 的明确欠账与用户新提出的键盘、项目复用、素材、Plugin 和动画场景合并判断。

## 产品判断

v0.5 已改善大项目日常响应。下一步需要补齐连续创作时的操作闭环：键盘在正确区域工作，Main 与衍生演讲互相可达，素材能查找和复用，外部 Agent 能读取当前叙事上下文，并能在同一份 PPTD 中编辑可重现的时间线。

现有永久身份、共用 writer、事务恢复、命名版本和本地项目结构继续承担持久化职责。

## 实际基线与缺口

| 领域 | 已有能力 | 本轮确认的缺口 |
| --- | --- | --- |
| 基础键盘 | 方向键 1/Shift 10 单位移动、Enter 文字编辑、Esc、常用复制/撤销/选择命令 | Tab 走 DOM 控件序列；缩放柄过多；侧栏焦点使画布操作失效；缩略图缺统一方向键导航；只读/保存中部分浏览操作被阻断 |
| Main/Presentation | 一份项目元数据中保存 Main、Section 和多个引用序列；不是两套 PPTD | 缺少衍生演讲总览和当前页使用关系；部分实际播放序列点击会误跳回主库 |
| 重复页面 | pageId 稳定，重复引用有 occurrenceId、独立备注和版本选择 | UI 对页面身份、本次出现、当前序位的解释和精确跳转不足 |
| 素材 | 原字节导入、内容散列去重、真实文件树、缺图诊断、命名版本素材归档 | 缺搜索、预览、used-by、直接复用与替换工作流；文件树截断未清楚展示 |
| Story/Agent | Main、Section、Presentation、逐页 Story；共享 REST writer、CLI 和 stdio MCP | 缺当前 occurrence 的完整上下文 briefing；MCP 的项目/演讲/素材入口和 Plugin 指南落后实际能力 |
| 字体 | 文档中字体请求收集、文字/表格样式与富文本渲染 | 字体可用性仍未验证；有效继承、富文本和实际字体栈需在渲染上下文检查 |
| 溢出 | 对象外框、旋转越界、图片裁切和缺失资源检查 | 缺当前渲染后的文字/公式范围检查 |
| 动画 | 未知动画字段保留；静态导出报告动画未导出 | 没有 PPTD 关键帧模型、时间轴、时间采样或播放编辑 |
| 长会话资源 | v0.5 降低首屏占用，20 轮操作已有记录；图表 SVG 缓存已有 32 条上限 | 图片 URL 使用整页 renderRevision；图表缓存缺总字节预算；实际影响需定向及连续会话验证 |

详细专项见 [键盘与 UI](AUDIT-V06-KEYBOARD-UX.md)、[项目与 Agent](AUDIT-V06-PROJECT-AGENT.md)、[动画调研](AUDIT-V06-ANIMATION.md)、[渲染诊断与资源](AUDIT-V06-RENDERING.md)。这些专项的代码入口和官方资料用于形成 [SPEC-V06](SPEC-V06.md)。

## 页面身份的决定

同一目录页在第 3、16、32、56 个位置出现时，页面的 pageId/短码保持不变，每次出现保留各自 occurrenceId；位置是当前序列计算值。修改主页面会更新所有 live 引用，固定版本仍保持原版本。

当不同出现需要不同高亮或内容时，作者可以选择明确的独立页面变体或命名版本。本轮先把已有复用关系、备注和版本选择做得可见、可定位；动画播放状态按 occurrence 重置。

## 验证材料

继续使用独立合成项目验证边界，并读取用户授权的 DNA TT PPTD 和 m6A PPTX 作为真实材料。所有修改、时间线试验、恢复和导出使用隔离副本。PPTX 可以提供真实对象、字体、动画使用需求；它本身不是已经实现 PPTX 导入编辑的证明。具体样本数量、原文件摘要与结果在执行后记录，研究内容和原始路径不进入可提交证据。

## 推进次序

先固化审计与规格，然后并行实现键盘工作台、项目/素材/Agent 上下文、动画模型与界面；集成字体/溢出检查和有证据的资源修正。随后进行源码、真实桌面、真实材料副本与长会话验收；补齐 Implementation/Validation/Release/Handoff，再集中同步重要里程碑。
