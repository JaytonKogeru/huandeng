# HUANDENG v0.7 — Implementation

日期：2026-11-08（Australia/Sydney）。依据 [AUDIT-V07](AUDIT-V07.md) 与 [SPEC-V07](SPEC-V07.md) 实施；最终平台结果与限制以 [VALIDATION-V07](VALIDATION-V07.md) 为准。本版不改变 PPTD schema，静态 PPTX/PDF/PNG 仍输出基础状态。

## 1. 责任与复核

三个专项代理先研究再审计。负责人分别检查原有文档、当前代码和证据，接受有依据的建议并写统一 Audit/Spec；随后将独占模块交给代理实现。负责人实现动态导出和集成，独立复审代理改动、实际 Windows 窗口、输出文件与故障验证结果。专项报告位于 `docs/research/V07-*-REVIEW.md`，具体代理交接位于相应 `*-IMPLEMENTATION.md`。

本轮没有机械应用 Taste-Skill：保留明确视觉层级、真实截图复核、短促操作反馈与一致控件；未引入营销页布局、额外字体、复杂视觉库或拖动阻尼。

## 2. 工作台与任务入口

- 项目标题、当前 Main/Presentation 集合、保存状态和文件动作以横向顶栏组织。长标题可截断，完整信息仍可访问；正常连接提示不再占用一行。
- 统一导出窗口承载 PPTX/PDF/PNG/MP4 的范围、设置、进度、取消和结果。演示保持直接入口。
- 原图片路径弹窗移除。工具栏“素材”进入现有素材库；设备导入为明确快捷动作，库中动作说明“导入并放置”。原有拖放、粘贴、复用和原尺寸比例继续使用共同流程。
- 保存按钮称“保存页面”，避免把各自有失败恢复语义的项目/Story/图表/动画草稿误称为一次原子保存。项目总览可直接进入编排。
- 动画预览临时让出基础属性栏，展示选中对象和返回基础编辑入口；用户手动折叠的偏好保留。移除画布虚增的固定最小高度，使较矮窗口打开时间轴时仍能完整适配整页；手动缩放不变。Portal 弹窗与按钮也遵循 reduced-motion。
- Windows 键盘回归发现路由提交竞争：焦点请求现绑定目标 pageId/occurrenceId，Enter 明确要求进入画布；旧页面提交不能消费新页面的焦点意图。

涉及 `huandeng.tsx`、`styles.css`、`authoring-workspace.tsx`、`thumbnail-rail.tsx`、项目/素材组件与 `export-dialog.tsx`。

## 3. 动画制作效率

新轨道仍以基础状态建立起点和终点，不猜测用户的目标姿态。创建后立即选中终点，将播放头移到终点，并提供具体数值编辑入口。可见时间字段统一秒，精度 0.001 秒；磁盘仍存整数毫秒。纯时间转换测试覆盖完整 0–600000ms 往返，拒绝无效值与不能表示为整数毫秒的输入。

快捷键帮助包含播放头和选中关键帧的实际方向键、Shift、Home/End、Space 行为。现有拖动取消、一次手势一次事务、失败草稿恢复和固定版本只读约束保留。

## 4. 长会话与素材资源

### 保存与历史

`getCurrentSnapshot()` 在文档队列上读取已经提交的状态，普通保存回读不再重复做外部磁盘刷新。事件 checkpoint 采用最小身份/hash 投影；文件观察刷新不再为无人使用的返回值复制全文。调用方可变 snapshot 继续隔离，CAS 仍依据真实文件字节，未降级为 mtime 或 TTL。

外部版本内存由全文集合改为摘要/索引及最多 8 条、约 4 MiB UTF-16 估算热内容。冷版本按需从原磁盘格式读取并校验，全部旧历史仍可恢复。初始化顺序读取，持久化历史读取并发限制为 8。只读会话观察写入独占临时目录，关闭清理，不写项目和永久历史。

### 高清预览

缩略图及素材网格请求独立预览路径。可用 FFmpeg 将 PNG/JPEG 派生为 320/640px 保比例 PNG；画布、素材详情、插入尺寸及成品导出使用原图。缺少编码器或格式不支持时返回经过版本校验的原图，响应标明降级原因。

真实资产 SHA-256 使用 revision 参数；页级或 stat 提示使用 hint。返回内容或 304 前都核对实际 bytes，旧版本请求不能收到新图片并被长时间缓存。首版采用 private/no-cache 与强 ETag。

原图读取之前最多两个活动槽、最多 32 个排队任务；同 hash/尺寸派生合并。派生磁盘缓存有数量与字节上限，在用文件被保护；进程超时、像素预算、关闭终止与原图回退均有测试。完整细则见 Spec 和性能专项交接。

## 5. 动态交付

### 数据流

`video-plan.ts` 为解析后的页面 occurrence 建立确定导出计划。重复引用保持顺序，固定版本保持对应画面；通过 occurrenceId 精确选页，只有页身份而存在多个出现位置时明确拒绝歧义。短码大小写兼容。

服务端冻结文稿及所用素材到每任务独立目录，生成一个 export renderer。`huandeng-export.tsx` 显式 seek 到帧对应时间，只挂载当前 occurrence；等待字体、图片和科学对象准备后截图。原有 sampler 计算每帧状态，截图写入 FFmpeg pipe 并等待背压，不保留全片帧集合。静页、cue 停留和末帧停留复用相同帧。

当前输出 MP4/H.264/yuv420p，无音轨；720p/1080p，24/30fps。最长 10 分钟、最多 18000 帧。静页默认 3 秒、动画末帧 1 秒、cue 额外停留默认 0 秒，导出前可配置并看到预计时长。

自主播放的 GIF/APNG/动态 WebP 和含自主动画/脚本的 SVG 明确拒绝，避免墙钟播放破坏确定性；PPTD 关键帧动画正常输出。静态格式仍使用基础状态，并在报告中标记时间线未导出。

### 作业、下载与失败

每项目同时一个重导出任务。API 返回 job id，GUI/CLI/MCP 查询准备、渲染、编码、完成、失败、取消状态。关闭导出弹层不丢失当前作业；404 过期状态恢复到可重新导出，暂时网络错误继续重试。

工作态在结束后释放 snapshot 与资产引用，完成成品从文件流读取。每任务下载不可变，后续同名导出不会改变旧链接内容。正常保留最近最多 8 个任务、15 分钟有效期；正在下载的文件延迟淘汰，项目 Exports 成品不会随过期删除。

发布先复制到同目录暂存文件，最终主文件 rename 才是提交点。在暂存期间取消保留旧成品；提交点后取消不能误标失败。旁路报告写入失败保留成功并给出警告，正确报告仍可从本次任务下载。

Windows 文件占用的故障注入验证了完成状态与清理状态必须分开：清理失败不推翻有效成品；内存先释放，保留目录所有权以重试，并限制失败清理任务数量。关闭先终止自有浏览器/编码器和文件流，再尝试清理，不干扰用户其他应用。

## 6. 接口与交付边界

CLI 增加 `video`、`export-status`、`export-cancel`。已有 MCP export 接受 MP4，增加状态/取消工具，工具总数为 17；仍使用同一文档服务、授权及事务边界。协议调用验证与真实 Agent 客户端安装分别验收，不能因为工具列表存在就声称 ChatGPT/Claude 客户端已安装。

编码器按显式 HUANDENG_FFMPEG、随包 tools、PATH 查找并验证 libx264。没有编码器时静态导出和一般编辑仍可使用，视频入口提供配置说明。当前安装机已有 FFmpeg；本版不自动下载或捆绑第三方二进制。

本轮没有增加任意运动路径、音频时间轴、页面转场、原生 PPTX 动画、PPTX 导入、独立 occurrence 视觉覆盖或跨机器协作。产品后续排序在 Release/Handoff 中根据实际验收再确定。
