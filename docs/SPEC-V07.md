# HUANDENG v0.7 — 工作台、长会话与动态交付

日期：2026-11-08（Australia/Sydney）。负责人根据 [AUDIT-V07](AUDIT-V07.md) 批准实施。基于 v0.6，不迁移 PPTD 文档模式，不改静态格式含义。

## 1. 结果目标

用户可以在较紧凑的工作台中明确选择项目/演讲、插入或复用素材、完成第一条动画，并将当前页或当前演讲范围输出成可播放视频。长会话不再因为每次导出或外部历史而保留所有素材/历史全文；普通保存减少可证明重复工作。保存恢复、单写者、原始资源和科学文稿均保持原有保护。

工作顺序为 Audit → Spec → Implementation → Validation。专项代理可实现自己的独占模块，负责人负责集成、复核、实际桌面验收和里程碑交付。新需求或实测发现导致范围变动时，在本文件补充决定。

## 2. 工作台与素材

1. 顶栏以单一横向基线显示项目名与当前集合；长名称截断并可查看完整内容。保存状态与文件操作相邻，正常连接不占第三行；重连、恢复、冲突和未保存草稿可见。
2. 单一“导出”按钮打开导出任务；“演示”仍可直接到达。紧凑窗口仍保留项目/集合、导出和演示。F6/Tab 顺序与视觉顺序一致。
3. “保存页面”及 Ctrl+S 的范围明确。项目、Story、图表、动画草稿保持独立提交与失败保护，有可直达的提示。不得通过串行独立写操作宣称原子全保存。
4. 素材面板是唯一默认浏览/复用界面；工具栏原图片入口定位素材面板，提供明确的快捷“从设备导入”动作。库中按钮称“导入并放置”，提示目标当前页；删除普通流程手输素材路径。拖放、粘贴、比例、撤销与缺图修复不退化。
5. 预览时不保留大面积禁用的基础属性栏；保留选中对象标识、预览模式与返回基础编辑。手动侧栏开关偏好不因暂时预览被覆写。
6. 主要控件/字段标签采用 12–13px 等现有系统角色，次级信息约 11px；减少常驻解释而非全局加大字号。沿用配色/字体及短促按压反馈；reduced-motion、立即焦点、无画布拖动延迟。Portal 弹层也遵循减少动态效果，保留居中定位；打开时间轴后的自动适配使用实际剩余高度，整页保持可见，不以固定最小高度挤出可见区；手动缩放仍允许滚动。快速缩略图切页/Enter/PageDown 的焦点恢复必须绑定目标 page/occurrence，旧路由提交不得消耗新导航的焦点意图。

## 3. 动画制作效率

- 新轨道的起点来自基础值；终点初始仍同值以避免猜测，但创建后选中终点、播放头置终点，显示“修改终点数值，然后预览”的具体行动并可聚焦字段。
- 所有可见时间输入统一秒，精度 0.001 秒，持久化仍是整数毫秒。无效/超范围输入有明确反馈；不会因转换静默漂移。
- 帮助说明播放头方向键、选中关键帧方向键、Shift、Home/End、Space 的现有实际行为。输入框保留原生按键；Esc 取消手势、一次手势一次提交。
- 有限改善命中区/数值编辑和模式说明，不在此版隐式录制画布姿态或加入任意运动路径。
- 项目总览提供进入编排的直接入口；保留尚未保存 Presentation 的独立编辑选择器。更新 PROJECTS 中过时 UI 名称和四位短码约定。

## 4. 内存与保存工作量

### 4.1 历史与快照

外部观察记录保留磁盘格式与全部历史。内存持摘要、按页索引与有字节/数量上限的热内容；内容按需读取，初始化避免同时解析所有完整文本。只读无法落盘的临时观察须保留正确行为且明确边界。回滚/列表/固定版本和元数据变化仍准确；坏记录不静默变成错误版本。

只读会话的新观察写入本机独占的临时目录，不写项目或永久历史；保留本会话全部版本，使用相同的有界热内容缓存，关闭时清理临时目录。临时磁盘不可写时明确报告历史保存失败，不丢弃旧版本或退回无限内存持有。

减少保存后重复磁盘刷新、事件 checkpoint 不必要 clone 等确定工作。保持返回 snapshot 隔离、CAS 真实 bytes 校验、外部同长度恢复 mtime 检测、恢复收据/重试/单写者事件语义。不得以 TTL 或 mtime 代替写入前验证。

以原隔离 80 页×64 对象脚本比较工作次数、延迟、post-GC heap、external/ArrayBuffer。进一步用至少 100 条外部版本验证热全文数量/字节有界和旧版本可恢复。Linux 结果与 Windows 结果分开记录。

### 4.2 素材

正确性先于缓存：带 revision 的资源请求必须确认该版本与返回字节一致。不得让旧 URL 返回当前新图后被 immutable 缓存。按内容 hash/尺寸区分的预览派生物使用磁盘或有限热缓存；原图保留导出与完整编辑质量。实际高清场景必须含至少 30 页/多张 4K 级图片，覆盖翻页、素材滚动、同图复用、替换和导出。若平台派生工具不具备，则不能声称预览已降采样；将实际测得的限制作准确记录。

预览接线细则：真实素材 SHA-256 使用 revision；页级 renderRevision、stat 和组合提示使用 hint。原图与预览请求在返回成功内容或 304 前核对内容版本，冲突返回 409。缩略图和素材网格使用 320/640px 保比例 PNG 预览，画布/详情/插入尺寸/导出保留原图。可选 FFmpeg 缺失、格式不支持或派生失败时返回已校验原图并标明回退；普通素材功能不依赖 FFmpeg。首版 private,no-cache + 强 ETag，不加 immutable。

读取原图 Buffer 之前最多占用 2 个活动槽，排队上限 32；同内容 hash/尺寸合并派生。session 自有磁盘缓存最多 256 项/128 MiB，在用文件不被淘汰；编码最多处理 32M 像素、默认 15 秒超时，关闭终止自有子进程和排队任务、清理临时目录。原项目素材不改写。文件读取以打开的句柄 stat 为准，只分配已验证的大小并额外探测 1 字节；提前 EOF 或增长返回 REVISION_CONFLICT，最终关闭句柄。缓存淘汰成功后才扣预算；临时目录仍被占用时保留所有权并暂停新派生，回退已校验原图，避免失败请求累积目录。

## 5. 导出资源生命周期

静态接口继续支持 PPTX/PDF/PNG 基础画面，报告保留 `TIMELINE_STATIC_EXPORT`。工作任务冻结 snapshot/素材，对每个任务使用独立工作目录与不可变产物。成功后释放 snapshot/素材 Buffer/结果 Buffer；下载从文件流读取。失败/取消释放工作资源且不返回成功产物。

完成态保留有限元数据，不指向后续会覆写的公共文件。定时过期清理，不依赖下一次导出；默认 15 分钟下载有效期、最多 8 个完成任务；下载中的文件不提前清理。任务目录清理由拥有该目录的 manager 管理；服务关闭停止任务并清理其临时内容。发布到项目 Exports 的用户成品不随任务过期删除。目录写入遵循 root containment，临时文件和最终 rename 保证失败不破坏已有文件。

集成复审明确发布提交点：主成品的原子 rename 之前发生错误，保留旧成品；此后的旁路 `.report.json` 更新失败，任务返回成品成功及明确 warnings，界面提示从本次 report URL 下载正确报告，不能把已经替换成品的任务标为整体失败。成品和报告不是两个文件的原子事务；不通过跨盘回滚或删除有效输出来伪装原子性。只读运行时输出目录使用经过约束的身份，逐层验证真实目录，避免用户可编辑 deckId 或符号链接引起越界创建。

集成故障验收补充：临时文件被占用不能覆盖已经发布的成功状态。完成后先释放内存引用，再尝试删除；清理失败提供警告并保留目录所有权供定时重试，删除成功后才移除记录。通常最多保留 8 个已完成任务；最多允许 8 个清理失败任务，达到上限后暂停新导出并明确提示，不继续无限增长。关闭仍终止自己的任务与流；无法解除的外部文件占用以诊断记录，不伪称完全清理。

## 6. 确定时间视频

### 输出与时间规则

- 第一交付格式 MP4 / H.264 / yuv420p，无音轨。可在编码器支持且验收完成后增加 WebM；未实现格式不出现在成功能力列表。
- 支持当前页（通过 occurrence 精确选择）及当前已保存集合，集合可以是 Main 或 Presentation；按解析后的 occurrence 顺序导出，重复出现不去重，固定版本遵循已有解析。
- 预设 720p 和 1080p，保持画布纵横比并取偶数宽高；默认 30 fps，可选 24/30，测试可用较低分辨率。输出像素/帧数/总时长在后端验证，最大 10 分钟、1080p 级像素面积、最多 18000 帧。
- 每页有时间线时播放至 durationMs，随后保留末态（默认 1 秒）；无时间线页面默认停留 3 秒。cue 不能无限等点击：用户设置每个 cue 的额外停留，默认 0 秒并明确显示。UI 在开始前显示这些规则和总时长；无声、无页面转场。
- 每帧由帧序号和 fps 推导时间，复用现有 sampler；cue 停留在准确 cue 时间，末尾停留采样 durationMs。禁止依赖录屏或 wall-clock requestAnimationFrame 决定动画进度。
- GIF/APNG/动态 WebP/自主运动 SVG 等素材要冻结为确定静帧或在开始前明确拒绝，并给出具体素材原因；不能悄悄实时播放导致每次输出不同。原文件不改写。静态公式/图表继续使用真实 renderer，渲染错误阻断。

### 作业流程

1. 入口先保存页面并要求辅助草稿处理完；显示范围、格式、分辨率、帧率、静页/末帧/cue 停留和可预期时长。
2. 服务端冻结确定版本，检测可执行编码器及所需 encoder。发现顺序：显式 `HUANDENG_FFMPEG`、可用随包工具、PATH。当前机器配置可由安装步骤写入已有宿主的受控配置；不硬编码开发机路径，不下载执行不明二进制。
3. 开始返回 jobId，轮询状态包含 preparing/rendering/encoding/completed/failed/cancelled、已完成帧/总帧、错误或下载结果。每个项目至多一个活跃重导出任务，防止多浏览器/编码器内存叠加。
4. 只挂载当前 occurrence，显式 seek 后等待字体/图片/科学对象准备，截图写入编码器 pipe 并等待背压；不在内存积累全视频帧。编码失败/浏览器退出及时终止对方并释放资源。
5. 取消先中止捕获/编码并移除临时文件；已完成并进入发布提交点的任务返回真实终态，不能把已发布成品删除。取消在复制暂存期间仍生效，原子 rename 开始才进入提交点。关闭导出对话框不自动丢失作业状态，可重新打开查看；轮询遇到任务 404 切换为可重试终态，暂时网络错误保留作业并继续查询。
6. 视频 API 采用共享授权/单写者服务边界；GUI、CLI 的参数与错误一致，已有静态 API 兼容。负责人在集成复审中决定同时扩展现有 MCP export 的 MP4 格式，并增加 status/cancel 两个作业工具，保持同一文档服务和授权边界，不另开网络服务或模型执行器。协议验收与真实 Agent 客户端安装仍分别记账。

### 编码器能力边界

本机 FFmpeg 的隔离 1 秒 H.264 spike 已通过；应用仍必须在打包环境里检测并验证。安装包若未包含 FFmpeg，发布说明明确外部工具要求；未检测到时显示可操作的配置说明。不能把单机成功称为所有机器自带视频编码器。

## 8. 分工与阶段边界

UI 代理拥有编辑器 route、工作台 CSS 和必要视觉组件；功能代理拥有 timeline、素材库、快捷键帮助、项目总览/编排与相应文档；性能代理拥有 store/page-history/persistence 的有证据优化和测试。负责人拥有导出前后端/编码器/作业、总文档、集成验收与发布。共享文件变更先交接，禁止互相覆盖。

本版不把任意运动路径、音视频同步、原生 PPTX 动画、独立 occurrence 视觉覆盖、双屏彩排、跨机器协作、PPTX 导入或真实 ChatGPT 私有通道计为已完成。实际 Agent 客户端入口可在本轮核心完成后继续推进，以真实安装/调用结果单独验收。完成本轮后重新按用户目标排序下一轮，而非机械穷尽所有研究建议。
