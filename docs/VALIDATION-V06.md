脚本为 [benchmark-editor-v05.mjs](../scripts/benchmark-editor-v05.mjs)。三轮均为同机、1600×1000、DNA TTT 80 页副本、当前页四个对象与七个缩略图，当前画布无图片；v0.5 为已发布包，v0.6 为开发宿主候选。

| 测量对象 | 循环数 | 启动记录（秒） | visual Delete 中位数（ms） | 持久化观测中位数（ms） |

## 8. 20 轮内存记录

| 指标（MiB） | 开始 | 20 轮后 | 显式 GC 后 |
| --- | ---: | ---: | ---: |
| Renderer JS 已用堆 | 17.26 | 25.24 | 16.51 |
| Renderer working set | 171.33 | 409.57 | 320.85 |
| 文档服务 working set | 207.59 | 262.8 | 本表无对应 GC 结论 |

JS 堆在显式 GC 后回落，说明这次短会话增长中有可回收对象；renderer working set 仍高于开始值，文档服务也有增长。堆、进程驻留内存和服务进程必须分别观察，**一次 GC 不证明无泄漏**。最终包及更长真实使用仍需保留内存采样。

## 9. 本轮失败、定位与修复

| 实际失败 | 证据与根因 | 修复及复核 |
| --- | --- | --- |
| Delete 界面反馈从约 24 ms 回退到约 63 ms | `Element.setAttribute` 插桩定位聚焦画布 `tabindex -1→0` 单次耗时 **44.2–46.2 ms** | 根固定为 0、frame 固定为 -1，程序管理对象焦点；修订 20 轮中位 25.4 ms，键盘 14 组通过 |
| 快速 Home → Enter → PageDown 到错页 | BrowserRouter transition 未提交，focus 已变化而闭包 `pageIndex` 仍旧 | 从同步 URL 的 page/occurrence 推进，并保护集合身份；原快速序列通过，不在测试中加延时 |
| 预览状态误显示为文档只读 | 基础编辑暂停使用的 `readonly` 混入保存状态，已保存动画不能准确显示状态 | 保存状态按真实 `pageReadonly` 判断，预览仍暂停基础写入；动画 15 组完成保存、预览与返回编辑 |

导航失败收据保留于 `.verification/v06-pre-navigation-fix`。后续 `selectPage` 从最新 URL 构造查询的补强发生在键盘 14 组收据之后，应纳入最终候选重验。

事件顺序复核还修正了画布 Esc 阻止 window bubble 手势取消的问题；活动手势优先直接取消，并由第 4 节真实 move/resize 断言证明没有产生误提交。
