# HUANDENG v0.15 产品与界面审计

2026-11-09。基线 f4a18ac（v0.14 交付）；依据本轮 8 张界面截图、实际源代码及本地项目只读检查。审计与验收分开：本文件记录发现，验收记录必须由实际运行补充。

## 判断

结构模型已经比界面成熟。稳定页面标识、主序列位置、章节、演讲引用、故事、备注、版本、修改回执都有实现；入口仍按逐次开发堆叠，导致用户难以判断“正在整理整套内容、编辑一页、准备讲述，还是连接助手”。本轮以任务层级重排，不重新制造一套文档模型。

| 当前入口组 | 所属任务 | 本轮处理 |

| 新页、复制、删除、排序、章节 | 内容组织 | 浏览视图复用现有事务；章节管理仍唯一编辑入口 |

## 动画现状与边界

当前文档模型支持出现、淡入、强调、移动、淡出、消失，支持单击/与上一动画同时/上一动画之后，以及延迟和时长；旧版关键帧仍可编辑。放映与预览共享播放模型。它是交互式幻灯片动画，不是动画视频生成。

需要实际验收：新建效果、保存、逐次点击推进、切页重置、倒退、重复引用、从当前页启动、退出恢复。PNG/PDF/PPTX 导出仍为静态布局，不能声称保留 PowerPoint 原生动画。

## 是否更适合 AI

可以确认的优势是本地结构化编辑、稳定标识与显示位置分离、版本约束写入、章节与演讲引用、故事和回执相连。这些让“改哪个对象、影响哪些引用、到底保存了什么”更可核查。尚无同题对照测试，不能据此宣称整体能力或美术超过其他产品。

- PowerPoint 已提供普通、浏览、备注页等任务视图，浏览也支持章节；Copilot 也可直接编辑演示文稿。应学习任务分工，而不是复制整条功能区。[官方视图说明](https://support.microsoft.com/en-us/powerpoint/training/choose-the-right-view-for-the-task-in-powerpoint)、[官方 Copilot 编辑说明](https://support.microsoft.com/en-us/powerpoint/edit-with-copilot-in-powerpoint)
- Google Slides 提供结构化 API；“可以被程序操作”不是 HUANDENG 独有。应比较事务、引用和可审阅上下文是否方便，而不是有没有 API。[Google Slides API](https://developers.google.com/workspace/slides/api/guides/overview)
- Kimi 官方将幻灯片生成纳入 Agent 工作能力；本轮没有同内容实测，不能断言其可编辑性或审美较差。[Kimi Agent 说明](https://www.kimi.com/en/help/agent/agent-overview)

仍缺：经作者认可的视觉参考与可复用风格约束、更系统的跨页一致性检查、意图到版式的可审阅选择、来源证据的对象级关联、完成前的实际渲染审美验收，以及动画交付兼容。结构正确不等于好看；默认三张圆角卡片、装饰渐变和无关插图尤其不能当成“AI 美术”。本轮插件明确参考页→意图/约束→预览→修改回执→渲染验收，浏览视图帮助人和 Agent 共同发现跨页节奏问题。

## 数据修改范围

私有项目不进入代码仓库或咨询会话。footer-correction deck 仅处理确认的页脚位置字段；section-divider deck 根据既有章节标题补封面，不编造研究结果或覆盖证据页。保存基线、变更回执与实际渲染在本地私有交付目录。
