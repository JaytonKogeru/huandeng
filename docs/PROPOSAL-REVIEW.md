# 审阅方案与保存冲突

从 Editor 0.23.0 起，可以把助手提出的修改放进待审列表，在实际页面上比较后再接受。这个流程适用于“先给我方案”的任务；已经授权的普通编辑继续保存，并可在历史中查看已保存修改。

## 让助手提交待审方案

助手先读取当前项目，使用当前页面和项目 revision 形成原有事务文件，然后执行：

```sh
huandeng --entry /absolute/project/deck.pptd propose /absolute/transaction.json --title "更新实验结果说明"
huandeng --entry /absolute/project/deck.pptd proposals
huandeng --entry /absolute/project/deck.pptd proposals PROPOSAL_ID
```

提交只保存待审记录，不改变页面、Story 或编排。事务结构和普通 preview/apply 相同；不要把说明文字当成事务。需要本机命令参数时，从目标项目的“助手接入 / Agent setup”取得配置。

## 在编辑器中决定

1. 打开“Activity / 活动”，选择“Review proposals / 审阅方案”。
2. 选择方案和受影响页面，比较当前页面、建议页面、备注与字段修改。使用位置会注明 live 引用和固定版本。
3. 接受后查看真实保存记录；拒绝会保留拒绝状态，不写入项目内容。

如果方案中的页面修改相互独立，界面提供按页选择。选择后先生成一个新的待审方案，需要再查看和接受；同一页作为一个完整组保留。结构、共享组件等复合修改不提供任意拆分。过大的方案需拆成可以完整显示全部受影响页面的组。

在等待期间项目或所引用的素材变化，旧方案不能继续接受。让助手重新读取最新项目，保留他人修改，用新的 requestId 提交新的方案。重新打开服务也需要重新形成审阅版本。

## 处理保存冲突

出现冲突时，自动覆盖保存暂停。本地草稿继续保留，选择“看差异 / Review differences”可并排比较本地草稿和最新保存页。

独立字段可以合并；同一字段被双方修改时，必须明确选择保留本地值。已删除的对象或变更了共享布局的对象，需要在新版本上重新构建修改，界面不会强行复活旧对象。

“采用新版本 / Use saved version”保留当前会话中可恢复的草稿副本。恢复草稿后，如仍与最新版本冲突，需要再次审阅并正常保存。副本最多保留最近十个页面，退出应用前应保存或复制需要的内容。

## 审阅事实与兼容性

接受由编辑器界面签发，记录绑定这份方案、当前项目和服务会话，并且只能使用一次。普通 Agent 凭证不能冒充这个界面的接受动作。所有实际保存仍经过共享 writer、revision 检查、原子保存和幂等回执。

这表示可以核验一次界面审阅，并不代表所有 Agent 编辑都必须经过强制审批。已经授权的普通 preview/apply 仍可直接完成。

0.23.0 使用本地协议 2。Editor、CLI 和插件需一起升级，随后重新连接原项目。旧连接会明确要求重新引导；不应通过复制 token、关闭认证或修改项目来绕过。项目文件、原始素材、稳定身份和现有历史无需迁移。
