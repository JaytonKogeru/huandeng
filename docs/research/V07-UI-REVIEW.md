# v0.7 UI 研究与只读审计

日期：2026-11-07 UTC。作者：UI 审计子代理。状态：**供主代理复核的研究材料，不是正式总 Audit 或实施 Spec。**

## 结论

用户指出的顶部拥挤有直接证据：项目名、演讲集合和保存／连接状态确实占三层，实际标题栏由 CSS 固定为 64px。v0.6 已形成安静的中性色、深绿选择色和统一按钮语言；下一轮的收益主要来自重新组织信息与操作，而不是换一套配色或增加装饰动画。

建议本轮优先处理三个问题：**标题栏的横向层级、素材导入与复用的统一入口、动画工作时的面板空间分配**。其次统一可读字号与说明信息密度，改善时间线的精细操作。现有键盘保护、预览只读保护、保存恢复提示和 reduced-motion 支持应成为改版约束。

本审计没有修改产品代码、安装 Taste-Skill、执行外部脚本、操作用户窗口或科研原稿。以下建议须由主代理结合功能与性能审计后决定。

对 HUANDENG 可借鉴的是：保持单一视觉系统，以真实前后截图核对结果，检查拥挤与溢出，保证焦点即时可见，尊重减少动态效果的偏好。其营销网站中的 hero、满屏章节、配色抽签、WebGL 与强视觉场景不应直接应用到幻灯片编辑器。此次只研究和筛选原则，未安装或执行该技能，不能据此宣称该技能已经改善了产品。

### 2.2 其他一手资料与学习所得

| 一手资料 | 学到的原则 | 对 HUANDENG 的取舍 |

综合这些资料与现有产品，工作台应把文稿画面放在中心，保留明确的当前模式、较少的常驻解释和稳定的操作位置。这个结论是本审计的产品判断，不是任何一个外部技能的强制规则。

## 3. 应保留的现有成果

1. `styles.css` 的浅灰画布、近白面板、深绿选择态与低对比边界已经一致；截图没有支持「必须全面换肤」的证据。
2. 字体栈包含 Geist、Segoe UI、PingFang SC 与 Microsoft YaHei UI。问题是字号角色与密度，不是缺少一套新的网络字体。
3. 左侧导航、右侧属性已有收起入口，动画区按需打开。不能把「仍可优化」写成「完全没有空间管理」。
4. 预览时基础几何编辑被禁止，避免将动画帧误写成基础版式。界面调整必须保留这个保护和清晰的返回编辑入口。
5. CSS 已有 70/140ms 按压反馈、160/90ms 菜单过渡、键盘焦点立即显示及 reduced-motion 分支。用户希望有细微动效，v0.6 并非没有实现。
6. 素材区已有搜索、过滤、使用位置与失效资源处理；技术检查已有按需展开和过期结果识别。下一步应优化层级，不要重新造一套同义功能。

## 4. 优先审计发现

优先级定义：P1 为本轮建议完成的用户核心体验问题；P2 为应纳入设计、按容量实施的改进。这里没有发现足以仅凭视觉证据判为 P0 的阻断。每项均区分事实与设计判断。

### UI-01 · P1 · 标题栏三层堆叠，文档范围与保存状态挤在一起

**证据。** `packages/core/src/app/routes/huandeng.tsx:1245` 起，在同一容器中依次放置 `h1`、演讲集合 `select`、保存与连接状态。`styles.css:554` 将 `.hd-titlebar` 高度设为 `4rem`，覆盖 JSX 的 `h-14`。两张实图均出现用户描述的三行；1600px 宽时，这一小块仍纵向拥挤，其右侧留有明显横向空间。右侧 PDF、PPTX、保存、演示与多个图标同时常驻。

**判断。** 这是可核对的结构事实。当前视觉拥挤主要来自不同信息角色混排，不能靠进一步缩小字号解决。单纯把高度由 64px 减为 56px 也不等于完成设计。

**建议。** 将项目名与当前演讲集合置于同一横向基线，允许长标题截断并能查看完整名称。常规保存状态放在保存动作附近或统一状态位置；「文档服务已连接」无需持续与文档标题争夺一行，重连、冲突、恢复失败仍要明确显示。合并导出格式到一个可发现的「导出」入口，保留显著的演示按钮。项目级操作留在标题栏，对象创建与选择留在工具栏。

**取舍。** 格式菜单会比独立格式按钮多一步，但可容纳后续动态交付，避免随着功能增加继续扩展标题栏。保存提示不能被误合并为一个无条件的「已保存」：页面、Story／编排草稿和动画草稿的真实状态必须保持准确。

**验证。** 在 1600、1280、1040 宽度及长中英文标题、长演讲名下，标题区域不再纵向三层堆叠，核心操作不被遮住。检查保存中、待保存、恢复、断线、冲突和只读引用状态。以实际布局、焦点顺序与截图验收，不能只检查 class 名。

### UI-02 · P1 · 「图片」与「素材」采用相同符号，用户难以预测两个入口的关系

**证据。** `huandeng.tsx:1499` 的素材标签与 `:1698` 的图片工具都使用 `ImagePlus`。后者打开 `:2139` 的「添加原始图片」对话框，既能选设备文件，也能填已有素材路径；`asset-library.tsx` 则有导入、浏览和「复用到当前页」。实图中两个相近入口同时可见。

**判断。** 功能并非完全等同：一个偏创建动作，一个偏已有资源管理。但当前图标与流程把这种区别交给用户猜测。Penpot 同时保留两者的事实说明「删除图片按钮」不是唯一合理答案。

**建议。** 用一个清晰的素材使用流程统筹两种来源：「从设备导入」和「从项目素材选用」。工具栏可以打开这个入口或直接定位素材面板；素材面板保留浏览、搜索、引用关系与复用。拖入、粘贴截图与快捷导入继续直达。若保留独立工具，文字和符号应分别表明导入动作与素材库位置，底层仍共用导入过程。

**取舍。** 如果统一入口迫使每次插图都先切换侧栏再找按钮，简化外观反而增加操作成本。要比较真实任务路径，不以减少按钮数量作为唯一成功标准。已有路径输入可作为次级高级入口，不应与可视素材选择并列为默认方式。

**验证。** 分别完成新文件导入、已用素材复用、拖入／粘贴、缺图替换四条任务；检查资源不重复导入、比例不变、撤销一致。用户应能从文案预测动作结果。功能实现和共享接口由功能审计合并决策。

### UI-03 · P1 · 动画任务出现两处属性区；默认固定侧栏进一步压缩制作空间

**证据。** `huandeng.tsx:219` 将动画预览纳入基础编辑 `readonly`，但 `:2017` 后仍保留整个 `PptdInspector`；其 `inspector.tsx:141` 宽度为 `w-72`。`timeline-panel.tsx:1045` 附近又有 `w-48` 关键帧属性区。时间线截图可见右侧基础属性大面积禁用，底部另有可编辑关键帧属性。左栏在 `huandeng.tsx:1470` 按标签切换 `w-64`／`w-80`。

**判断。** 1600px 实图中仍可操作，不能宣称已有遮挡或功能失效；但工作模式与空间分配不匹配。以当前名义尺寸计算，1040px 窗口在 320px 左栏和 288px 右栏同时显示时只剩约 432px 中部宽度，尚未扣除边界。该数值是 CSS 布局推算，不是新测量结果。v0.6 已允许手动收栏。

**建议。** 动画编辑时让属性呈现与当前任务一致：选关键帧后，在一个主要属性区显示时间、值和缓动；预览时基础属性可缩成只读摘要，提供返回基础版式的明确入口。根据可用宽高提供紧凑布局，保留用户手动收栏选择。左侧在切换页面与素材时尽量保持稳定宽度，或明确采用可记忆的面板宽度。

**取舍。** 直接自动关闭右栏虽然释放空间，却可能丢失用户的参考上下文；统一属性也会改变焦点位置。因此应保留当前对象／关键帧标识、编辑模式标识和可预测的返回路径。面板展开不应通过反复动画缩放画布制造视觉漂移。

**验证。** 普通编辑、动画编辑、播放预览与返回编辑之间，焦点和选中对象保持正确；基础几何不被误改。记录窗口、画布、各栏的实际 bounding box，覆盖 1600×1000、1280×800、1040×680；1024px 只作为独立压力条件。窄窗与低高度下关键动作仍可达，页面整体无横向溢出。

### UI-04 · P2 · 10–11px 元数据已经扩散到操作标签，字号角色不够明确

**证据。** 标题栏保存状态为 10px；素材名 11px、资源状态与路径 10px；时间线字段标签、轨道按钮和说明多为 10px；技术检查的解释区域同样是 10px。位置包括 `huandeng.tsx:1263`、`asset-library.tsx:303` 以后、`timeline-panel.tsx:173`／`:952`、`technical-qa-panel.tsx:154`。实图中这些小字的视觉权重接近，用户必须靠阅读区分名称、状态与指导。

**判断。** 这是可读性与角色层级的设计问题；本轮没有做所有颜色组合的对比度测量，也不能把 10px 本身自动判定为 WCAG 不合格。既有 v0.6 审计也已把小字列为后续边界。

**建议。** 定义少量工作台文字角色：主要控件／字段标签可从 12–13px 起评估，次级元数据约 11px，项目／面板标题建立稳定层级。ID 与路径只在需要辨认时强调，完整值可查看或复制。字体大小应与行高、控件高度一起调，不应全局把编辑器改成营销网站的 16px 正文。

**取舍。** 全面增大字体会增加表单高度和换行；优先提升用户需要读懂或操作的文字，减少常驻说明，再评估密度偏好。沿用已有字体栈，避免引入字体下载与不必要的风格分叉。

**验证。** 在实际 Windows 100%、125%、150% 显示缩放下检查中文、数字和图标基线；分别查看浅色、深色、禁用态、选择态与焦点。抽查真实 computed font-size、行高和对比度，不以截图主观评分替代测量。

### UI-05 · P2 · 常驻说明与高级检查争夺属性区的注意力

**证据。** 无选中对象时，右栏同时包含 Story、版式配方、技术检查与图层（`huandeng.tsx:2035–2060`）。`technical-qa-panel.tsx` 已折叠检查列表，但未检查状态仍有多条解释；素材栏长期显示目录／引用规则，详情重复展示路径、预览和历史引用解释。时间线底部长期显示保存说明和静态导出边界。

**判断。** 这些信息有真实价值，尤其失效资源、字体未验证、固定版本及静态导出边界；问题在于正常状态与异常状态的视觉预算过于相似。技术检查已经有部分渐进展开，不能描述为「全都没有折叠」。

**建议。** 默认显示紧凑的摘要、状态与行动；把规则解释放到相关帮助、展开区或首次使用状态。未选对象显示页面层级信息；选中对象优先显示该对象相关属性。错误、冲突与恢复行动可获得更高权重，正常已连接／没有问题无需不断占用多行。有关导出是否静态的说明应在导出选择处再次明确。

**取舍。** 不能为追求干净而把所有状态塞进一个 tooltip。必须保留固定版本只读、编辑同步到主页面、动画预览以及保存失败等能改变用户决策的信息；这些状态适合简短但常驻的标识。

**验证。** 对正常、空数据、缺图、字体未测／回退、过期检查、固定引用和未保存草稿分别截屏；检查每个异常都能定位并采取行动。正常状态下用户首先看到当前页／对象与操作，而非解释段落。

### UI-06 · P2 · 时间线的精细操作与读数系统还可以更统一

**证据。** 时间线播放与时长用秒显示（`timeline-panel.tsx:783`、`:812`），关键帧和 cue 字段用毫秒（`:1051` 以后）。关键帧按钮使用 `h-7 w-5`，轨道删除按钮覆写为 `size-5`；轨道名称固定 160px 且为 10px，属性区固定 192px。实际截图的原生 range 控件较粗，与下方精细轨道的视觉重量差异明显。

**判断。** 毫秒存储合理，但 UI 同一任务中切换单位会增加换算；名义 20px 宽的目标在密集轨道下需要精确点击。本轮未新测点击失败率，也不将相邻关键帧可重叠的情形简单等同于无障碍不合格。

**建议。** 默认显示一致的秒数表达并保留毫秒精度，输入、键盘微调和辅助读数明确当前单位。关键帧图形仍可小，交互命中区应更容易选取，并在密集相邻帧下配合缩放或明确的选中策略。让播放头、轨道选择、关键帧选择和只读预览各有一种稳定反馈。

**取舍。** 不应机械套手机 44px 的控件大小；放大命中区也不能造成相邻帧不可预测地抢事件。时间线需要更完整的缩放／滚动／数值编辑方案，主代理应与动画制作效率工作合并，不作为单独换皮任务。

**验证。** 30 秒、两分钟、多个近邻关键帧、长对象名、10 条以上轨道；覆盖拖动、键盘移动、直接输入和 cue 导航。验证 Esc 可取消，撤销仍以一次手势为单位，不引入时间／位置漂移。

### UI-07 · P2 · 微交互应完成一致性复核，重点是焦点与模式反馈

**证据。** `styles.css:616–701` 已实现按钮、弹层与 reduced-motion 规则，`button.tsx` 也已有 hover／active／disabled／focus 样式。工具区当前通过 `data-hd-focus-region` 与 F6 导航分区，没有据此声称已经采用 ARIA toolbar 的完整组内方向键模式。

**判断。** 这项是既有能力的一致性复核，不是「补上缺失动画」。用户想要精致、自然的工具，应优先改善当前模式、选中态、成功反馈和输入焦点，避免对画布坐标和拖动添加惯性延迟。

**建议。** 保留当前短促的按压和弹层反馈；新素材入口、导出菜单、模式切换沿用同一时序。选中与焦点即时可见，保存成功无需反复弹出提示。若工具栏引入 roving tabindex，必须同时实现方向键、首尾与焦点回收，并明确排除原生表单输入。

**取舍。** 不建议为满足「有动效」而给侧栏宽度、画布缩放、每次选页和长期播放状态增加循环动画。也不在缺少性能证据时引入新的动效依赖。

**验证。** 鼠标、键盘、reduced-motion 与浅／深色四类交互状态；F6／Shift+F6、Tab、Enter／Space、Esc 和原生输入方向键都要复核。按压反馈不改变最终几何位置，播放中的选择反馈不增加无关整页更新。

## 5. 给总 Audit / Spec 的建议接口

| 阶段 | 建议落点 | 完成证据 |
| --- | --- | --- |
| 本轮优先 | UI-01 标题层级与导出组织；UI-02 素材入口；UI-03 动画空间 | 同一合成项目的前后实图、明确状态矩阵、真实键盘与鼠标任务 |
| 随上述修改一起收敛 | UI-04 字号角色；UI-05 常驻信息密度；UI-07 微交互一致性 | 任务标签可读、异常仍可见；没有新增键盘或 reduced-motion 回归 |
| 动画效率阶段合并 | UI-06 时间读数、命中区、密集轨道；UI-03 关键帧属性归属 | 多轨真实操作、关键帧往返读数一致、一次手势一次撤销 |

建议在正式 Spec 中先确定三种模式的布局责任：**基础编辑、动画编辑、播放预览**。然后再决定组件拆分，避免仅在当前 JSX 上不断增加条件和解释文案。素材入口改动由功能审计确认数据与操作语义，空间与动效改动由性能审计检查重排和重绘影响。

## 6. 候选验收矩阵

- **窗口与内容：**1600×1000、1280×800、1040×680；短／长项目名，长演讲名，多页、多素材、10+ 轨道。1024px 压力测试与正式最小窗口分开记录。
- **状态：**基础编辑、动画编辑、预览、固定版本、实时引用；保存中、待保存、断线、恢复、冲突、只读。各状态的信息准确性先于美观。
- **可读性：**浅色／深色，真实 Windows 显示缩放 100%／125%／150%；中英文字段、数字、路径、长图层名和禁用态。截图之外记录关键 computed styles 与对比度结果。
- **操作：**打开／切换项目与演讲集合、导入／复用素材、关键帧创建与修改、导出与演示；鼠标、Tab、F6、方向键及原生输入边界。
- **动效：**默认与 reduced-motion；按钮焦点、展开／关闭菜单、切换面板、选关键帧。确认不存在拖动延迟、画布几何过渡或不必要的连续动画。
- **证据：**正式候选生产包的原始截图与操作收据；记录基线、窗口、状态与构建身份。功能断言、视觉判断和性能数据分别陈述，失败不以美化截图掩盖。

本报告提出的是候选优先级。正式总 Audit 应记录主代理对每条建议的采纳、调整或拒绝理由；只有通过该复审的内容才进入下一版 Spec 与实施。
