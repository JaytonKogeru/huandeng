# HUANDENG v0.11 independent UX audit B

Date: 2026-11-08. Baseline: `editor-v0.10.0` / delivery `40ef08e`.

## Scope and method

This is an independent source-based review of the same authoring journey as audit A: open a Project, recognize Main Slides and Presentations, organize Sections, insert and edit slides, inspect supporting files, and save or deliver. It examines the v0.10 implementation and synthetic acceptance material. It is not a new live UI test, performance measurement, or review of a private research Project. No private slide text, figures, screenshots, file paths, or names belong in this report or repository fixtures.

The reported difficulty is supported by the implementation. Existing capabilities are often separated from the place where a user expects to act. File preview, insertion between thumbnails, and collapsible Section covers need actual new interaction; Quick Layout and Presentation removal already exist but have poor discovery.

## Findings and decisions

## Interaction details worth settling before implementation

**Section cover and selection have different jobs.** Selecting its thumbnail should open that Slide. A distinct disclosure controls the member list and supports keyboard activation. Collapsing does not remove pages, change export order, or change Presentation references. Search should reveal matches without permanently overwriting the user's collapsed state. Navigating to a hidden member should reveal it. Pages before the first start remain visible outside Sections. A missing/duplicate start requires a diagnostic; it must not silently assign unrelated pages. A cover slide is still an ordinary editable Slide, and making it a cover should not redesign it.

**Insertion needs a real location, not an index guessed later.** Resolve a clicked gap to its neighboring stable identities against the current Main snapshot. Use the existing writer/revision checks. If another edit invalidates that location, report the conflict and retain the intent. Search and collapsed Sections must not silently turn “before this Slide” into “after the current Slide.” Keep Main insertion and Presentation reference editing distinct.

**Read-only file preview should stay a slide-authoring aid.** Preview text safely without running scripts or interpreting project HTML as application code. Bound file reads and image decoding; reject paths outside the Project, including escaping links. Keep the selected file identity attached to the request so a slow response cannot replace a newer selection. Closing Preview restores the previous Inspector/Notes context and does not discard drafts. A first release does not need an embedded general-purpose code editor.

**Quick Layout should reuse the author's decisions.** A title style needs position, size, font, alignment, and appearance, with authored wording excluded. Capture must identify the chosen text object explicitly. Applying a title style should not infer that all large text is a heading or move existing images. New blank-page scaffolds may create ordinary editable objects; applying styles to existing pages needs an explicit target and reversible transaction. Project-specific style data stays with that Project and out of distributable examples.

**Normal status and recovery remain distinct.** Reducing banner noise must not hide failed writes, unsaved drafts, external conflicts, or recovery actions. The same draft and retry contracts must continue to protect typing when changing Slides, Files, Notes, or Project views.

## Focused acceptance journeys

1. Create an empty Presentation, find its management action without scrolling through content, remove it, save, and confirm every Main Slide and recorded version still exists.
2. Open/close the Slide and Section chooser by pointer and keyboard; verify consistent wording, icon state, focus, and duplicate-append feedback.
3. Mark several synthetic slides as Section starts, collapse/expand them, search for hidden members, insert before and inside a Section, move a start, and reopen the Project. Check stable IDs, current order, membership, and missing-start diagnostics.
4. Insert at the first, middle, and final thumbnail gaps, including an active search and a collapsed Section boundary. Undo/redo and reopen; verify exact position and fresh identity.
5. Preview a PNG, Markdown file, JSON file, and script as read-only content; switch quickly between files, close/reopen Preview, and verify the current Slide and unsaved text/Story/Notes drafts remain. Verify bounded/unsupported/error states using synthetic files only.
6. Open Quick Layout through one disclosure, capture a synthetic title's style, apply it to an explicitly selected title and a new Section cover, undo, and reopen. Check original wording, figures, and unrelated object geometry.
7. Select Arial/Times New Roman, an available open-license family, a missing family, and a custom stack; compare the status shown in Settings, canvas rendering, and existing export/font diagnostics. No unverified cross-machine rendering promise.
8. Reproduce ordinary unsaved organization and an empty Presentation without stacked top warnings; reproduce a genuine synthetic write conflict and confirm recovery remains visible and actionable.

## Extension priorities

The existing shared writer and Agent bridge already provide the right integration base. Useful future adapters are a citation-aware figure/library browser, a scientific data/plot importer, and a project-specific style assistant that proposes bounded edits. They should import local originals and use the existing preview/apply transaction path. A marketplace, arbitrary plugin execution, and a new network tunnel are not prerequisites for this polishing release.
