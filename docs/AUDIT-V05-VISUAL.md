# v0.5 视觉与交互审计

审计基线：`8798d8f`，正式 v0.4 的源码与文档；重点反馈为 [Issue #6](https://github.com/JaytonKogeru/huandeng/issues/6)。本文件记录界面判断、已落地调整与实际验收边界。完整功能覆盖见 [AUDIT-V05-COVERAGE.md](AUDIT-V05-COVERAGE.md)。

## 结论

v0.4 的主要视觉问题是几个开发阶段的界面没有形成统一规则：桌面启动页为深绿，React 界面保留上游朱红，favicon 又是橙色幻灯片；项目编排几乎全英文，页面编辑则以中文为主；身份、顺序、文件路径都挤在相似的小字层级中。已有面板布局可继续使用，优先统一品牌、语言、选中状态和常用工具的行为。

下一版采用中性色工作区、白色内容面、深绿选择色与既有 H 标识。内容与画布保留主导地位。工具组、边界、字重和即时反馈承担层级。

## 界面审计与已实施改进

| Before | After | Why |
| --- | --- | --- |
| `desktop/icon.svg` 的绿 H、`app/favicon.svg` 的橙色图形、编辑器中的字体 H 三套标识 | 桌面 SVG 为单一源；`HuandengMark` 与 favicon 使用同一图形，ICO 同步；增加派生脚本与哈希清单 | 启动菜单、窗口、浏览器预览和应用内标识指向同一产品 |
| React 朱红选择色与绿色开始页分离 | 深绿品牌与浅色选中底；深色模式使用可读的浅绿强调 | 选中、焦点和品牌使用一致规则 |
| 默认无明确中文字体堆栈 | Geist / Segoe UI 搭配 PingFang SC / Microsoft YaHei UI / Microsoft YaHei | 中英文界面使用稳定的系统字体回退 |
| 顶部 56px 放下标题、集合与状态三行 | 64px 标题栏；缩放栏保持紧凑；工具栏减少空隙 | 给项目状态留足行距，维持画布面积 |
| 工具按钮统一排列，状态区与操作区缺少明确间隔 | 工具组使用细分隔线；激活工具与导航标签使用一致选中底 | 在较高密度下仍能看出操作类别和当前工具 |
| 窄窗口的插入工具容易互相挤压 | 工具栏允许横向滚动，按钮保持可点击尺寸 | 宽度不足时仍保留全部操作入口 |
| 欢迎页以大标语和斜叠纸片占据主要区域 | 左侧打开/新建，右侧最近项目；项目名、位置、打开日期分别排列 | 让日常恢复工作成为主操作 |
| 最近项目最多显示六项，等待时仍可重复点击其他项目 | 显示宿主返回的最近项目；等待时禁用操作；保留文件已移动状态 | 避免排队重复打开，明确本次操作状态 |
| `Project & Story`、`Save project` 等英文与中文页面面板混用 | 项目、演讲、故事、章节、版本、快速布局使用统一中文词表 | 降低理解和寻找操作的负担 |
| 项目面板与历史对话框优先显示 S1/S2 | 优先显示四位短码；tooltip 继续提供 UUID 与旧编号 | 页面身份和当前页序清楚分开，历史引用仍可追溯 |
| 新插入对象在图层中显示 `node-…` 长 ID | 有文本或自定义名称时保留；其余显示椭圆、线条、图片、图表等实际类型，ID 放在 tooltip | 用户能直接理解对象列表，永久标识仍可用于定位 |

界面实现集中在 `packages/core/src/app/styles.css`、`components/brand-mark.tsx`、`components/pptd` 下的 project / design-intent / recipe / page-history 面板，以及 `packages/desktop/welcome.*`。`scripts/sync-brand-assets.mjs` 和 `packages/desktop/brand-assets.json` 维护品牌资产。

插入工具选择、画布放置与缩略图性能由本轮编辑器实现负责，属于同一体验里程碑；这里的样式与这些操作的选中状态衔接。代码复核同时发现并推动修复了图形预览与最终轮廓不一致、菜单图标被默认尺寸压小、插入手势的多指与失焦取消、Shift 线条在边界处偏离约束方向，以及缩略图重排后当前页未跟随滚动等问题。

既有移动、缩放、旋转手势也补齐了同一取消规则：活动手势只接收发起指针的事件；第二指不能改选区或结束操作；失焦、失去捕获、Esc 和画布卸载恢复操作前的几何值。监听器先移除再释放捕获，避免释放触发的事件重复提交；取消后晚到的 pointerup 不写入文档。

## 动效约定

本次参考仓库中的 `emil-design-eng` 和 `review-animations` 设计规则，按实际操作频率选择反馈方式。

| 场景 | 实现 | 目的 |
| --- | --- | --- |
| 鼠标按压常用按钮 | 按下 70ms，释放 140ms，最多缩放到 0.97 | 立即确认输入；连续按压可中断 |
| 开始页主按钮 | 按下 70ms，释放 140ms，缩放到 0.98 | 保持相同反馈，适应更宽的按钮 |
| 下拉菜单、右键菜单、弹出层 | 进入 160ms，退出 90ms；从触发点展开 | 保持控件与菜单的空间关系 |
| 键盘焦点与快捷操作 | 按钮不位移；菜单获得键盘焦点时关闭过渡 | 高频操作立即响应 |
| 页面内容、删除、拖动、页面切换 | 未添加装饰动画 | 用户直接看到操作结果 |
| 减少动态效果偏好 | 取消按压位移和菜单缩放，保留短淡入；等待指示静止 | 保留状态信息并减少运动 |

没有增加动画依赖。新增运动仅使用 transform / opacity；工具数量、布局尺寸和画布几何不参与动画。

- 既有桌面 PNG 为 512×512；ICO 包含 16、24、32、48、64、128、256px。派生脚本保留这些尺寸，并可重生全部资产。
- 相关样式、品牌、面板、启动页与脚本的 focused Biome 检查通过；`welcome.js`、品牌派生脚本与项目验收脚本语法检查通过。
- `scripts/verify-project-v04.mjs` 已适配中文标签与页面短码，原有项目编排、固定版本、演讲备注、冲突草稿与导出等验收逻辑保留，等待完整桌面回归运行。
- 指针生命周期、插入几何和文档草稿契约共 39 项单元检查通过，涵盖另一指针事件、五种取消路径、取消后不提交、正常结束只提交一次，以及四个方向贴边时的 45° 约束。`@open-slide/core` 类型检查通过。
- 颜色按实际十六进制值计算的对比度：正文/背景 14.54:1；次级信息/背景 4.90:1；侧栏说明/背景 4.54:1；主按钮文字/背景 9.33:1；错误信息/背景 6.17:1。此项只验证所列配色。
- Windows Electron 38.7.2 的真实编辑器验收通过 8/8，记录位于 `.verification/editor-v05.json`；使用独立三页合成项目，渲染器错误为 0。1600×1000、1024×768 与深色模式截图已逐张查看。
- 三张截图中工作区品牌、中文标签、页面短码和选中状态一致；主操作可达，画布无裁切，右侧长面板可滚动。对应窗口的 scrollWidth 分别为 1600、1024、1600，未出现整页横向溢出。
- 本地 Linux Chromium 的 socket 限制没有被当作视觉通过的依据；上列视觉结论来自实际 Windows Electron 截图。品牌栅格派生和启动页状态另由桌面验收补充。

## 实际视觉核查

已核查同一份隔离测试项目的正常窗口、1024×768 紧凑窗口与深色模式。紧凑窗口的常用工具、保存/导出/演示入口仍可达；页面短码和页序可区分，长标题按所在区域截断，右侧面板可独立滚动。截图暴露的图层 UUID 显示问题已修复；窄窗口缩放控件因提示隐藏而靠到左侧的细节已交由主编辑器调整。页面级故事名称按词表统一为“幻灯故事”。这些后续细节应随最终候选截图再次核对。

后续桌面核查还应查看菜单展开方向与开始页有最近项目、无最近项目、文件已移动、打开等待、打开失败等状态，并按减少动态效果偏好确认按钮和菜单不再位移。

截图确认层级和密度，操作过程确认响应与反馈。当前里程碑优先完成流畅度与插入、身份等高频交互；字体存在与文档溢出检测另列后续专项。

## 后续可改进项

属性面板仍有较多 10–11px 的次级信息，应根据实际 Windows 缩放和用户反馈继续调整。底层返回的诊断信息需要统一的界面呈现。品牌当前保留用户已安装的绿 H 设计，未来若改变标志美术方案，可替换单一源并重新派生资产。
