两组各 122 条预览响应；实际可见的 12 张缩略图天然尺寸为 320×180 对 3840×2160。按内容版本和尺寸去重的 31 种正长度表示合计 **797,062 bytes** 对 **119,177,776 bytes**，约为原图的 **0.669%**。另外各 90 条预览响应没有正长度。画布和详情保留原尺寸，静态 PNG 导出 1920×1080；同长度、恢复 mtime 替换仍返回正确版本冲突，源文件校验通过。

第一轮后 CDP 计数均为 2011 nodes、2 documents、397 listeners；挂载量一直为 6 previews、7 renderers、15 images。最后一个间隔 GPU / Tab 驻留趋缓，但 JS 仍小幅增加、服务仍有波动。最终 Tab working set 有编码器约 387.09 MiB，原图回退约 439.19 MiB；峰值约 515.14 / 687.44 MiB。GPU 最终值接近，不能声称 GPU 驻留大幅减少。

切页计时包含 Playwright 点击以及新页面和原尺寸图片准备，不是渲染一帧的耗时或拖动 FPS。正 Content-Length 的响应按内容版本和尺寸去重后代表已观察的图片表示大小，不是总网络传输量；缺失或 0 长度不能按零传输处理。

这轮必须同时观察 JS、Tab、GPU、文档服务、DOM/监听器与已挂载 renderer 数量。显式 GC 只能说明部分 JS 对象可回收，不能证明浏览器图片解码、GPU、native allocation 或服务进程已经无泄漏。派生缓存和历史的明确上限成立，也不自动推导整机驻留内存必然收敛。

## 8. 实际发现的回退及处理

| 失败或风险 | 根因与处理 | 验证 |
| --- | --- | --- |
| 快速 Home/Enter/PageDown 焦点丢失 | 路由提交可能消耗无身份的 focus 请求；绑定 page/occurrence 并明确 Enter 目标 | 保留原快速序列，源码及最终 EXE 重跑 |
| 1040×680 预览底部裁切 | min-h-64 大于时间轴上方实际剩余空间；改为可收缩高度 | 七处整页边界断言及深色实图 |
| reduced-motion 按钮仍下移 1px | LightningCSS 将 translate:none、scale:none、transform:none 合并成只重置 transform，独立 translate 残留 | 使用 initial 和 active 覆盖，检查编译后 CSS 与真实按压；保留焦点和 Dialog 居中 |
| APNG 自主播放绕过 guard | PNG 可能含 acTL 动画块 | 真实两帧 APNG、静态 PNG 文本避免误判，失败后可重试 |
| status 404 后一直忙碌 | 查询失败未进入可重试终态 | 实际窗口注入 404，旧真实任务待完成，再新建成功 |
| 发布/清理失败混淆成功 | 主成品、报告和目录删除不是一个原子事务 | 发布点、旁路警告、内存先释放、目录所有权与有限重试的故障测试 |
| stat 后全量读取可超预算 | 原图并发增长时 readFile 无界 | 句柄 stat、精确分配、有界读取、额外 1 byte 探测和 finally close |
| 缓存删除失败丢预算/所有权 | 先扣预算再删除 | 成功删除才扣减；失败暂停新派生并回退原图，关闭保留诊断 |
