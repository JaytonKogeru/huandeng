## 4. 布局、字体与视觉的专项判断

### 布局起点

现有三个配方分别为“原图与图注”“两组证据图”“原图与局部放大”。`recipes.ts` 保存普通对象和槽位绑定，手动几何、裁切、字体成为覆盖项；已删除槽位不会自动复活，软件升级也不自动重排。`recipe-panel.tsx` 将它们作为可选折叠工具。因此，其数据模型已经支持作者持续修改，而非把整页锁成模板。

模板感的剩余来源是默认生成结果：三种固定槽位、同一套间距和字号容易被 Agent 机械套用。改进应落在使用方式和初始参数：按具体图板比例与内容密度选择布局，保留长短标题、证据主次和局部空白；把入口清楚称为可选快速布局，提供可理解的几何参数与解除关联。无需为了“去 AI 感”增加随机不对称或自动审美评分。完整新模板库低于基础编辑流畅度。

### 字体与文字溢出

字体检查建议先覆盖实际有效主题、页面覆盖、对象和富文本中的字体请求。桌面可对照系统安装字体，浏览器检查实际加载及 fallback；结果应区分已确认可用、确认回退、无法核实，不能只凭 `document.fonts.ready` 宣称原字体存在。字体环境的有效摘要应参与相关页面的渲染身份，使跨机排版变化能反映在旧评审状态中。

溢出检查先从实际渲染完成的文本/公式 DOM 测量做起：对比可见范围、元素框和页面范围，定位对象并提示。PPTD 允许有意的文本越界，检查不应自动缩字或重排。原生 PowerPoint 有自己的排版引擎，因此浏览器检查、对象回退完整性和 Office 最终页面仍是三项不同证据。这些是比新增图表族更有价值的下一批科研交付改进。

### 编辑器美术

编辑器需要形成稳定的工具层级：主动作有明确位置，次级功能按使用情景展开，面板密度和字阶一致，选中与保存状态易读。按钮的悬停/按下、菜单进入、面板展开可使用短促过渡，并接受系统减少动效偏好。动效优先说明动作与反馈，不等待动画结束再接受输入。画布内容应保持作品自身的排版，编辑器装饰不参与自动改页。

## 7. 建议下一里程碑：日常编辑体验

建议 v0.5 交付 **大项目流畅编辑、常规画布插入、清楚的页面身份、专业统一界面**，让已实现的 Main/Presentation/Story/历史能力更适合持续使用。

开发顺序为：先测清加载与提交路径并减少等待；再做放置工具、身份和菜单；随后完成品牌、工具栏、面板和状态动效；以真实桌面连续操作验收。字体/溢出作为其后的科研交付重点，有可靠且范围明确的实现可在同阶段补入。

| 场景 | 验收观察 |
| --- | --- |
| 大项目打开 | 分别记录冷/热条件、服务/文档/首屏/首次可编辑；不等待全部离屏缩略图才能编辑 |
| 连续编辑 | 插入/删除/撤销/移动的画面反馈与保存分别计时，报告中位/P95，操作无漏失 |
| 缩略图 | 搜索、远端跳页、重排、固定版本与重复页定位正确；有限渲染窗口 |
| 保存与协作 | 同页过期请求仍拒绝，发送中继续输入保留，外部素材替换更新相关画面 |
| 插入与键盘 | 点击/拖拽放置准确；Esc 取消；文字输入焦点与 Delete/Backspace 不冲突 |
| 产品视觉 | 典型桌面和较窄窗口可读；主要动作好找，品牌一致，保存/冲突/选中状态清楚 |
| 已有能力 | 页面恢复、主库/演讲引用、科学对象与导出维持原语义；科研原稿字节不变 |
| 里程碑交付 | 完成相关测试、Release/Handoff、真实包与安装验证，再集中同步私有 origin |

性能对比应保持同一机器、同一材料和明确缓存条件。这样可以判断下一版是否改善实际工作，而不仅是某个合成测试的数字。
