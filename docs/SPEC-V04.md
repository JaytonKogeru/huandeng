# HUANDENG Editor v0.4 — 完整科研静态编辑核心

本阶段细化 [Master Product Specification](SPEC.md)，沿用 M1–M5 的保存与编辑基础。审计基线为 `64c9e7b5b00b1bf158fbc5c3cca3c176156cfb71`。完整能力矩阵与边界见 [AUDIT-V04](AUDIT-V04.md) 和 [PowerPoint 对照](POWERPOINT-COMPARISON.md)。

## 1. 同项目的两种 Slides

每个项目目录只有一份 Main Slides：原 `.pptd` manifest、独立 `.page` 文件及素材库。一个项目可包含多个 Presentation Slides，各自持有有序引用、受众、目的、结论和备注。所有引用绑定本项目，不能以外部路径或副本目录充当第二个 Main。

只建立一个 Section 层级。标题可以叫 chapter、part、方法或结果，数据结构不叠加三个同义层级。页面最多属于一个 Section，也允许暂未归类。Section 保存自己的页序；Main manifest 顺序不因此改变。Presentation 可引用整节或单页、重复引用、重新排列。整节引用动态跟随章节成员；转换为单页引用后固定其组成与顺序。

默认引用当前 Main Slide。每个单页引用可以改为固定一个明确命名的页面版本，且可以拥有自己的演讲者备注（包括明确空白）。固定版本只读预览，不得自动退回当前页面。演讲的预览、缩略图、放映和导出必须使用相同解析结果；重复页面以 occurrenceId 区分，pageId 保持原永久身份。

缺页、缺节、缺少或损坏的固定版本必须显示原因并阻止不完整交付，不静默跳页。页面移除保留 tombstone；恢复同一 pageId 后引用可重新成立。项目编排集中显式保存，使用 manifest/metadata CAS；有草稿时保留文字、阻止离开和导出，冲突后不覆盖他人改变。

## 2. Story 的三个叙事层级与逐页意图

- Main Story：全项目科学问题、主要受众、整体结论。
- Section Story：每一部分回答的子问题及结论。
- Presentation Story：本次报告的听众、目标和希望留下的认识。
- 逐页 designIntent：该页目的、要保留的构图、证据角色、来源与 revision 绑定的作者评审。

上述字段可留空，不强迫每一页套模板。Agent 自己记录的理解不能伪装成作者原话或批准。技术 QA 应定位缺图、越界和不支持对象；不制造主观“去 AI 风格”总分。

## 3. 页面身份与页面版本

永久 UUID/pageId 不改变，既有四位字母数字 shortCode 不改变。新增稳定的用户可读别名 S1、S2……；它们不随插页、重排或删除重新编号，也不复用已删除页面的号码。当前位置仍是单独的显示序号。旧短码及 UUID 均可继续用于 API/CLI 定位。

自动保存、Undo 操作记录、命名页面版本分开。普通移动、改字不会生成命名版本。完成一轮修改后，由用户或明确授权的 Agent 主动记录名称，如“组会定稿”。记录请求有 page/metadata revision 和 requestId，重复重试不会多造版本。

命名版本保存页面源、该页设计元数据、有效主题、画布尺寸和引用的本地素材。原始图片按 SHA-256 内容去重存入项目，不依赖 Git，也不依赖当前电脑的运行时目录。恢复只改当前页及其页级元数据，不改别的页、不覆盖共享现用图片、不改页序/身份。恢复本身可撤销，但不自动新增命名版本。

外链媒体须先导入项目才能记录可靠的可携带版本。损坏归档、过期 revision、不同画布尺寸或不属于该页的版本应明确拒绝。完整项目复制是当前跨机器携带方式，不承诺分布式自动合并。Git 保留为独立的工程/代码里程碑工具。

## 4. 科学对象与直接插入

保留同一 PPTD 模型和事务写入，复用 KaTeX、ECharts、Font Awesome Free、PptxGenJS 及 MIT 许可的旧 open-pptd MathML→OMML 代码。

| 对象 | 本阶段核心要求 |
| --- | --- |
| 公式 | LaTeX 源可改；行内/独立公式与 MathML 正确显示；可支持公式输出原生 OMML |
| 表格 | 插入、逐格编辑、行列增删、合并拆分、列宽与样式；原生 PPTX 表格 |
| 图表 | 13 类渲染、数据编辑、常用样式/坐标轴；6 类基础图及可支持组合为原生 PPTX 图表 |
| 图标/形状 | Font Awesome Free 三套图标；21 种常用形状；不手工复制庞大图标库 |
| 分组 | 稳定子对象引用，组合/解组、移动/缩放/旋转、复制重映射、正确删除与撤销 |
| 图片 | 文件选择、拖入、剪贴板导入；内容去重、保留原始比例和原始字节 |

PowerPoint 不能原生承载或暂未支持的对象按局部图片回退并保留原 PPTD 源。回退原因精确到 pageId/elementId。不允许把整页截图宣称为完整可编辑 PPTX。

## 5. 验收与发布

必须通过静态检查、类型检查、核心回归，以及实际 Windows 桌面测试。桌面检查覆盖打开/编辑/自动保存/Agent 更新/冲突/历史/重开/新建。新专项脚本覆盖科学对象菜单和属性、Main/Section/Presentation 编排、命名版本、重复引用、放映和不同演讲导出。

必须在实际 PowerPoint 打开生成的 PPTX，检查无修复提示、原生表格/图表/分组、嵌入的数据和公式显示，实际导出图像观察。真实科研文稿使用只读检查或临时副本；不把用户原稿作为测试写入靶。

发布保留用户已有未提交文件，先验证候选包，再安装到既有桌面路径，核对快捷方式与源码 build marker。达到里程碑后一次性推送私有 origin 与版本 tag，不发布 npm，不向 OpenSlide upstream 推送。

## 6. 明确保留的后续范围

完整 PowerPoint 导入/回导、Slide Master/SmartArt/OLE、录音视频/完整动画时间线、独立双屏排练、云端共同编辑、任意注册 React 科学组件及统计绘图全套误差模型不属于这次静态编辑核心承诺。上述差异必须在审计和发布说明保留，不能用“产品完成”隐去。
