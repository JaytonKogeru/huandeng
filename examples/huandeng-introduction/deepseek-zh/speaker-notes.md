# 保存的演讲备注：deepseek-zh

从实际保存的 Main 和 Editor 正式解析的演讲生成。命名版本与单次引用备注由 Editor 解析；以下备注不作改写。

## Main

页数：22.

### 1. 一份可以 继续修改的幻灯片

Slide ID: CZD7 / Main position: 1

开场：今天不先讲功能，先讲我为什么做这件事。组会、投屏、导师一眼看出 AI 质感；我只想改两页，却得到几份副本；以及我发现，幻灯片如果没有人的故事，再漂亮也像一份标准答案。这一页先把问题提出来。

### 2. 一个项目，一个写入器

Slide ID: Z4XP / Main position: 2

先把产品说清楚：项目目录是文档，Editor 是工作台，插件或连接器只是把外部助手接到同一个写入器。它不是把项目复制给每个助手，也不是让每个助手各改一份。

### 3. 从组会说起

Slide ID: 4ST8 / Main position: 3

章节停顿。先从一个具体的组会现场讲起，不从产品功能开始。

### 4. 导师一眼就看出来了

Slide ID: UGA7 / Main position: 4

组会现场。PPT 放出来没多久，导师或同事就认出了 AI 风格。它看起来太完整、太均匀、太安全：每块都填满，每页都同样重要，每句话都不会出错。真正缺的是取舍：不知道这场报告要让听众记住什么。

### 5. AI 质感，不是丑

Slide ID: PQQR / Main position: 5

先承认 AI 已经会排版。真正让我不舒服的，是它太完整、太均匀，完整到没有取舍。这里说的是我自己的观察，不是模型评测；我不给模型排名，也不把个人感受写成研究结论。

### 6. 改两页，为什么多出三份副本？

Slide ID: 2Z2N / Main position: 6

第二个问题更具体：我只有两页要改。很多 agent 有防御性，不会直接覆盖原件，而是另存一份；轻微改动也另存一份。副本一多，历史就散了。这个图是示意，不是产品界面。真正要改的不是 AI 的性格，是修改的单位。

### 7. 编辑器

Slide ID: 5MNK / Main position: 7

从组会问题转到工具本身：先看项目结构，再看工作区。这里不是第二段故事。

### 8. 一个工作文档

Slide ID: 5HUQ / Main position: 8

这是实际工作区：左侧页面与章节，中间画布，右栏属性和 Story，顶部是浏览、大纲、章节、备注、历史。它不是一个画布加文件菜单，而是一份文档的多个视图。截图来自公开示例项目，不是这份介绍本身。

### 9. 第 4 页会变，这一页不会

Slide ID: 88WA / Main position: 9

跟 AI 说“第 4 页”很危险：页面一移动，第 4 页就换人了。所以每一页有一个四字 Slide ID，界面上显示在位置旁边；内部还有永久 page UUID。日常交流用 Slide ID 就够了。这样我们说的和改的是同一页，历史也才有地方挂。

### 10. 改过什么，能看回来

Slide ID: AVJE / Main position: 10

这一页用本项目的真实历史界面说明：页面有操作记录和命名版本；恢复只改这一页，不是整份 deck 的回滚。左图是 7PV4 的「历史」工作区与命名版本，右图是同一页一次已保存修改的只读预览；两图都是 2026-11-11 从本项目截取。

### 11. 文件夹就是项目

Slide ID: G8WH / Main position: 11

打开项目文件夹或 deck.pptd，0.19 都支持；一个目录只解析一个入口。目录名可以加 .huandeng 后缀，但不是必需，也不会获得系统级双击关联。移动项目要带 pages、media、.huandeng。PPTX 也有包结构，HUANDENG 是把工作目录和页面服务显式化。

### 12. 页面不是一张截图

Slide ID: 4USM / Main position: 12

一页不是一张图。文字、图片、表格和线都有 elementId、bounds 和内容；助手可以直接定位一个对象，检查边界，读取 revision。截图仍然要用来判断构图和可读性，但它只是审阅面，不是整份文档。

### 13. 一页能承载真实证据

Slide ID: WMFA / Main position: 13

这一页作为编辑器的科学证据示例：Dickerson–Drew DNA dodecamer，PDB 1BNA。结构图是本轮从 PDBe 取得的沉积结构图；表格的 12 个 C1′–C1′ 距离由同一轮下载的 1BNA.pdb 坐标重算，与旧表一致。距离是同一结构中的 12 个位置，不是独立重复实验，也不是氢键长度。页面保留原生表格和来源。

### 14. 素材不是插图，是证据

Slide ID: 7PV4 / Main position: 14

素材库不是装饰图片的仓库。这一页的结构图是本轮从 PDBe 取得的 1BNA 沉积结构图，曲线由本轮下载的 RCSB 1BNA.pdb 坐标重算后用 matplotlib 重绘；URL、时间与 SHA-256 在 sources/independent-2026-11-11/acquisition.json。旧的共享 plot 仍留在历史文件里，但不再挂在这张页面上。

### 15. Story 告诉助手该保留什么

Slide ID: UZKY / Main position: 15

为什么故事能减少 AI 质感？因为它先规定取舍。项目 Story 说为什么做，章节 Story 说这一段为什么在这里，页面 Story 说这一页要证明什么、必须保留什么，讲稿说怎么讲。Story 不是讲稿，也不是审美批准；它是给 AI 的 alignment，不保证一定做对。

### 16. 一次修改，只动这一页

Slide ID: CKFY / Main position: 16

具体看一次修改：同一页 XZJN 的右栏从原生卡片换成真实截图，并补一行来源；标题、说明、左侧文字、Story、讲稿与 Main 位置都不动。两帧是同页、同视图、同缩放的真实 Editor 画布区域。这不是整页重做，也不是另存一个文件。我要的是改哪一页，就只动哪一页。

### 17. 一份内容，多次出场

Slide ID: XZJN / Main position: 17

同一份研究要面对不同听众。组会讲下一步，会议讲结论，评审要证据。页面不复制：Main Slides 是同一批页面，Presentation 只改这次的选择、顺序和讲稿。上图是本项目 Editor 的完整窗口（页面 Z4XP、项目面板在左），框内是项目面板里的「Z4XP 的使用位置」；下图是从同一张截图同一区域放大的可读细节，显示它用于 2 场演讲，并列 Main Slides、完整介绍与短版。

### 18. AI 在同一页上改

Slide ID: 2FMW / Main position: 18

这是我对第二个问题的回答：不要让 AI 再生成一份 deck，让它在同一个项目里改那一页。客户端读取 Story 和 revision，提交事务；共享写入器做版本检查、预览、应用，再返回回执。标识只说明支持的产品，不代表官方背书。

### 19. 几个助手，一个写入器

Slide ID: 5ZZM / Main position: 19

几个助手可以接同一个项目，但不是同时改所有东西。不同页面可以各自保存；同一页会 revision 冲突，即使改的是不同对象；Main 页顺序归 manifest；Project Story、Sections 和 Presentation 配置及其引用顺序归 metadata，需要协调。活动面板记录声明阶段和已保存回执，不是在线状态、自动章节锁或排班。内容到美术的交接也要先读已保存 operation 和 revision，再 preview、apply、render。

### 20. 它可以交出去，也还没做完

Slide ID: 6DVM / Main position: 20

最后，它仍然要能交出去：PPTX 可继续编辑，PDF 固定版式，PPT 项目留在自己手里。但我不想把它说成完成的 PowerPoint 替代品。任意 PPTX 往返、完整母版、独立演讲者窗口都还没做。边界写清楚，才知道能托付什么。

### 21. 站在开放工作上

Slide ID: K9P9 / Main position: 21

这一页把来源和边界一起说清楚。OpenSlide 是编辑器代码基础，MIT；OpenPPTD 只贡献公式转换模块，不是整个文档模型；PptxGenJS 生成 PPTX。GitHub 标记表示 OpenPPTD 仓库，不是它的 logo。HUANDENG 与 Kimi 没有隶属或背书关系。右侧列出当前仍未完成的能力。

### 22. 从这份项目开始

Slide ID: QHUX / Main position: 22

最后给一个可以马上做的动作。打开项目文件夹，或其中的 deck.pptd；一个目录只放一个入口。打开后从 Agent setup 接上已有助手，让它先读 Story，再只改一页；预览、应用、看历史。交付 PDF/PPTX，但把整个项目目录一起带走。目录可以命名为 Study.huandeng 这样的后缀，但不是必需，也不会因此获得系统级双击关联。

## 完整介绍

页数：22.

演讲级备注：

从组会要讲什么出发，用 Story 说明每一页为什么存在、要保留什么。中间以一次只改一页的修改讲页面身份与历史，以 1BNA 结构和重算的距离曲线讲证据如何保存，最后把同一批页面复用到下一场演讲。

这个演讲解析后的页面顺序与备注，与上面的 Main 完全相同。
