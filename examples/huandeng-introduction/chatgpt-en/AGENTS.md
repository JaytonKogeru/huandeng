# Introducing the HUANDENG workflow

## Purpose and audience
Explain how people and agents keep editing, reusing and delivering the same slide project. The audience is presentation authors and open-source contributors.

## Page contract
- The Main has 22 slides. Slides 3, 8 and 17 are title-only Section dividers with one text object.
- Every slide has a white #FFFFFF background. Text uses #202423 and secondary text #616A67.
- The canvas is 960×540. Ordinary titles use 30, body uses 18–22, Section titles use 34. Body text is regular.
- Use Arial. Keep each page focused; place extended explanations and sources in speaker notes.
- Use actual Editor captures with original pixels, audience language and provenance. Feature details need readable task crops.
- Do not add decorative arrows, circled steps, gradients, placeholder charts or repeated cards.

## Editing and delivery
- Preview and save changes through the shared writer instead of overwriting page files.
- Preserve slide identity, Story and the references in full and short Presentations.
- Frame a real content slide and a divider before expanding substantial changes.
- Inspect every rendered page and the contact sheet for text fit, image quality and repetitive pacing.
- PDF/PPTX are static delivery formats. Use the Editor for the live click sequence.
- Image provenance lives in assets-provenance.json. Licenses and acknowledgments live in the repository.
