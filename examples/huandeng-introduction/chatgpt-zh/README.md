# HUANDENG：从自己的故事，继续同一份工作

在 HUANDENG Editor 中打开 [deck.pptd](deck.pptd)，并保留整个项目文件夹。

作者希望 AI 帮助制作幻灯，也希望保留自己的故事、判断和原始证据。组会上，完整的一套页面可能仍然没有讲清真正想讲的事；五十页里改两页，又可能多出一整份副本。这份介绍沿着这些经历，讲清 HUANDENG 为什么立项、架构如何回应问题、实际怎样使用，以及它借鉴了哪些工作。

## 本轮修订

本轮由 **ChatGPT 6 Astra 主会话亲自修订中文页面**，承接前一轮分段 subagent 的创作基线，并使用本轮 subagent 的调查与独立审读。当前 Main 保存了 **31 页**。中文版按自己的叙事组织，不强制与英文逐页对应。

封面和内容页使用精确水印 `chinese chatgpt 6 astra + subagent`。真正的章节过渡页**只有标题**，不带水印、页码、副标题或装饰。这个水印记录中文版本的创作沿革，不意味着本轮每一页由 subagent 起草。

现有安装的共享 writer 是 0.19.0；Project Rules 的实拍来自已完成构建及检查的 0.20.0 本地候选版。本稿已完成本轮内部视觉与输出复核；候选版尚未公开发布，内部复核也不等于作者已经最终验收。

## 在故事里理解 Editor

开场从组会与修改经历讲起：作者想保留什么，重复副本为什么妨碍继续工作，故事为何先于页面。接着解释 Story、项目文件与架构，再用完整 Editor 确立位置，让具体操作有清楚的入口。

实际示例呈现原始素材、一次明确的修改、专业科学图和保存结果。稳定页面身份与历史解释“改过之后仍是同一页”；浏览、大纲和备注帮助作者重新审视讲述顺序；演讲引用让同一批页面服务下一次组会。人和 agent 的协作，以及正式致谢，共同收束这个故事。

先在**浏览**中读完整节奏，再回到具体页面查看 **Story** 的意图和保留条件，用**备注**阅读讲述内容。教学局部应能沿着整窗位置和相同标记找到，不能只靠一个脱离环境的裁片。
